# 测试策略

## 分层

| 层级 | 目标 | 最低要求 |
|---|---|---|
| 单元 | 领域不变量、算法、Rule、错误路径 | 快、确定、无外部依赖 |
| 架构 | 模块、领域和跨仓依赖边界 | 自动阻止非法依赖和循环 |
| Schema/契约 | Scanner、REST、MCP、Agent 输出 | 正例、未知字段、无效枚举、兼容线和引用闭合 |
| 集成 | PostgreSQL、Scanner adapter、Gateway 下游 | 使用真实兼容实现或受控 Testcontainers |
| 黄金/样例 | Fact/Finding/Evidence/Diagnostic | 固定 digest，至少重复三次并规范比较 |
| 端到端 | 每阶段的可演示用户旅程 | 少量、稳定，覆盖关键成功与失败路径 |
| 安全 | 越权、路径、执行、网络、泄漏、注入 | 高风险失败为零，不允许人工豁免掩盖 |
| 性能/恢复 | 扫描、API、工具、部署 | 固定输入和环境，先记录基线再设预算 |

## 修改规则

- 缺陷先增加能失败的复现测试，再实现修复。
- 不得删除测试、降低断言、吞异常或改样例期望来迎合错误实现。
- 未实际运行的检查必须标为“未运行”或“受阻”，不得称为通过。
- 当前阶段先运行最小相关测试，再运行仓库完整质量检查。
- 跨仓库变化同时运行生产者、消费方和兼容组合测试。

## 阶段重点

- 阶段 1：Scanner 模型、Rule、黄金结果、重复性、CLI 与输入安全。
- 阶段 2：Platform 模块/权限/迁移、Scanner 消费方和 Compose 端到端。
- 阶段 3：增量基线、CI 退出码、Webhook 幂等和审计。
- 阶段 4：结构化 Agent 输出、证据引用、降级、Token/成本和案例留存。
- 阶段 5：Gateway 授权、参数、限流、取消、并发和审计。
- 阶段 6：黑盒评估、基线比较、Prompt Injection 和越权零容忍。
- 阶段 7：备份恢复、优雅停机、发布回滚、故障手册和多语言契约。
