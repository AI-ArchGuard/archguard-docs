# 阶段四个人 Agent 可用化与黑白工作台设计

状态：Draft。所有者已要求建立持续目标并批准先看交互原型；完整产品设计、日常真实使用授权及新的真实验收预算仍待确认。本设计不授予真实调用次数或费用。

## 目标

让个人用户用自己的 DeepSeek 官方 API Key 完成阶段四真实验收，并能在简洁的 Web 中使用文档、Finding 解释、所选 Finding PR 摘要、引用、低风险建议、追溯、凭据与设置。完成最终候选、关闭/回滚/恢复、制品及唯一报告证据后，再关闭阶段四。

界面参考所有者指定的 [DeepSeek Harness 官方展示](https://www.deepseek.com/harness/)，采用紧凑侧栏、中央工作区、结果优先与按需展开详情。保留 ArchGuard 品牌及治理用途，不安装或移植 Harness，也不复制其插件、终端、任意工具和通用聊天能力。

## 当前事实

- [Platform #43](https://github.com/AI-ArchGuard/archguard-platform/issues/43) 与 [Deploy #10](https://github.com/AI-ArchGuard/archguard-deploy/issues/10) 在本次只读核对时仍 open。已实现合成能力、官方响应适配与受控真实批次接线，真实成功验收与发布未完成。
- 普通 Finding/PR 入口仍走 synthetic/disabled 请求；当前 live 入口绑定单个 synthetic Project、来源和两个模板。打开展示开关不能把它变成日常真实调用。
- 历史真实解释失败及 UNKNOWN 费用/预留保留；不能复用旧摘要授权，也不能宣称后来的离线诊断已证明其根因。
- 前一任务的650个手写文件中文注释已保存为本地提交，尚未推送。本任务保留这些内容和原工作区用户修改，独立分支交付。

## 使用体验

### 布局与主题

采用可收起侧栏、当前 Project 选择、单一内容区和按需打开的右侧引用详情。左侧主要入口为工作台、扫描、治理、架构文档；底部为模型/项目设置、主题和账号。保留已有登录回调与资源深链接。

提供浅色、深色和跟随系统的偏好；浅色为白底与黑灰文字，深色为近黑底与白灰文字。使用共享语义色变量、统一字号和间距、细分隔与清晰焦点，取消大面积渐变、卡片阴影和装饰色。主题偏好可保存为非敏感 UI 值，不能持久化 Key、Token、结果或授权事实。移动端使用可关闭抽屉，不横向挤压正文。

### 工作台与结果

中心工作区先呈现当前可操作资源、解释/摘要动作和结果；首次进入给出短标题与明确入口。输入使用选定 Finding、可信 PR 修订及文档版本，不把自由文本聊天画成已有功能。没有历史列表 API 时不虚构“最近会话”；原型中的示例记录明确标注。

结果先显示结论、规则依据、建议、证据覆盖与可点击引用。Prompt/模型/Schema/traceId/完整版本摘要收进“运行详情”；文档及 Evidence 在侧栏/抽屉查看。失败、证据不足和费用未知必须有准确短状态，不能伪装成空白、零值或成功。

项目创建、仓库注册、规则编辑和文档上传从列表主页面按需打开，避免每页先展开大表单。保留加载、空数据、权限错误、失败恢复与键盘操作。

### 简化说明与设置

重复的固定边界和工程说明归入设置/帮助与折叠详情。真实收费操作、删除/撤销及未知结果的影响说明保留在操作当下，避免把关键确认藏入帮助页。风险接受不预勾、核对时间不伪造、费用或发送不隐式批准。

Key 页面继续由浏览器短暂提交、后端加密托管，支持添加/替换/删除和只读元数据；只在模型设置出现，不部署模型或让浏览器直连 DeepSeek。保存 Key、登录、切主题、打开设置和刷新结果均不能产生模型请求。

## “全部开放”的范围

第一层是所有已实现的阶段四功能均能在导航中找到，具备清晰可用/待配置/权限状态；模型关闭时文档、扫描与治理仍可使用。

第二层默认按所有者的“全部开放”解读为：配置完成后，在明确启用的个人 Project 中，直接为选定 Finding 发起真实解释、为选定 Finding 集合发起真实 PR 摘要，而不要求用户手填合成模板/来源卷/批次 ID。此层目前缺少生产运行路径，是待批准的实质增量，不能仅靠 UI 折叠或去掉后端守卫实现。

日常模式需先新增 ADR/需求增量，由 Platform 冻结单独的个人使用授权、资源选择、不可变来源快照、请求及费用账本契约。验收批次仍保持 SYNTHETIC_ACCEPTANCE，旧批次和历史不升级；新模式与其分开追溯。继续保持模块化单体、最小投影、Project 隔离、默认关闭、当前凭据版本、Schema/引用校验、幂等、一次尝试和审计。新增迁移只能追加，不改已发布的16个迁移。

界面应将首次启用做成简短设置流程：录入 Key → 核对个人范围与预算 → 启用所选 Project。能够由系统验证的运行版本、来源摘要和配置事实由系统提供，需所有者亲自确认的风险保持显式动作；不能用自动填值伪造实际检查或接受。

日常模式的数据边界沿用已接受的个人范围：仅本人有权外发的非敏感材料、选定 Finding 的既有最小字段投影、Evidence 元数据/位置和明确选定的文档片段。不给模型增加源码文件、源码片段、完整报告/文档、凭据、个人敏感信息、客户/第三方保密资料或其他 Project 数据。引用对象仍由后端在当前授权下重新解析；原型中的代码证据只来自预置合成展示，不代表增加真实请求字段。

## 协议与费用

本次已只读核对 [官方 Responses 文档](https://api-docs.deepseek.com/guides/responses_api/)、[模型价格](https://api-docs.deepseek.com/quick_start/pricing/)及[更新公告](https://api-docs.deepseek.com/updates/)。当前仍列出官方 Responses、deepseek-flash 与 DeepSeek-V4.1-Flash-1017。实际发送前仍须重新验证有效快照，不以当前网页读取延长旧确认有效期。

沿用现有固定官方目标、非流式、无工具/会话/代理/重定向和不自动重试的边界；不借仿照界面更换协议或开放 Harness 工具能力。外层兼容与业务输出均依离线固定案例和明确版本验证，不能为了真实成功接收任意未知字段或伪造引用。

新的合成真实验收预算尚未收到有效答复。草案为解释、摘要各至多一次、串行，每次 USD 0.35、总额 USD 0.70；仅是待确认提案。解释成功且可信费用结算后才发送摘要，失败或 UNKNOWN 即停，不补发。日常使用次数/日额度、接受范围与有效期另行冻结，不能把本次两次验收的预算解释为长期费用授权。

保留完整请求6000字节、输出1500 Token、输入8000为调用后阈值的语义；保守预留、实际用量、UNKNOWN 与供应商账单分开表述。本地控制不承诺供应商硬限费。历史 UNKNOWN 不删除或假定归零。

## 交付顺序

1. 先评审本交互原型并冻结完整设计，明确日常范围及新的验收预算。
2. Docs 新决策/需求 → Platform 日常契约与准入/离线回归 → Web 消费；UI基础外壳/主题可先独立交付并保留既有功能。
3. 更新固定兼容候选，核对 PR 与合并后 main CI；处理当前 Web 锁文件已有3高危/2中危依赖审计问题，独立小变更升级且不降低门槛。
4. 在新授权下准备关闭候选，验证实际制品和来源/凭据版本/确认/价格及运行绑定，完成用户所需登录/安全输入；从不在聊天索取 Key 或密码。
5. 只用批准的合成数据执行新的真实解释与摘要，验证引用、不可变文档、状态恢复、实际 usage/延迟/费用/审计及确定性门禁隔离。
6. 核对关闭出口、最终候选回滚/恢复与历史保留，发布个人版制品、同步矩阵、合入唯一阶段报告和 main CI，再关闭相关阶段 Issue。Gateway 与正式 Evals 不提前开发。

跨仓库只通过版本化公开接口协作。回滚先关闭新发送入口/Project/模型出口，再回退应用，保留迁移、凭据密文、证明、历史解释、费用与审计记录。

## 验收

- 黑/白主题覆盖全部既有路由、表单、错误、空状态、弹层与引用；320px起无横向溢出，键盘、焦点和收起导航可用。
- 结果优先；不要求正常用户反复输入工程 ID，不丢失未提交表单/进行中读取，不通过卸载组件重置固定请求状态。
- 页面操作不产生隐式模型请求；双击/超时/刷新/失权等原回归保持；可信引用、版本追溯与 PASS/FAIL 不变。
- 对日常模式单独验证选择范围、数据准入、授权/版本变更、额度/幂等/失败恢复，不能仅用合成专用路径证明日常功能完成。
- 所有测试与真实证据分别记录，未执行者明确未执行；以最终运行事实证明验收，不用原型或假 HTTP 替代。

## 本次原型边界

原型只使用本地合成展示数据，无网络 API、真实账号、模型调用、Key输入或业务持久化。支持双主题、侧栏、示例资源选择、结果、引用与设置的交互评审；不是正式实现、成功验收或阶段关闭证据。
