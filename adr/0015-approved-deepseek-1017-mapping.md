# ADR-0015：本次合成验收的 DeepSeek 1017 映射快照

- 状态：Accepted；所有者已明确批准本次映射更新，工程跟进及具体运行绑定未完成，真实出口继续关闭
- 编写日期：2026-10-19
- 所有者批准日期：2026-10-18；公开授权记录见 [Platform #43](https://github.com/AI-ArchGuard/archguard-platform/issues/43#issuecomment-6251981882)
- 决策者：ArchGuard 项目所有者
- 部分替代：仅替代 [ADR-0014](0014-personal-token-admission-and-cost-reservation.md) 对本次合成真实验收沿用旧模型映射的假设；原协议、数据、Token/费用、授权次数、技术关卡及历史记录保留，已接受 ADR 正文不改写

## 背景

ADR-0014 以 2026-10-15 的模型映射作为批准时假设；[DeepSeek 官方更新公告](https://api-docs.deepseek.com/updates/)于 2026-10-17 公布 `DeepSeek-V4.1-Flash-1017`。验收准备期间发现批准快照与新公告映射不一致，依原决策暂停真实发送并复核。所有者于 2026-10-18 明确批准仅将本次合成验收的 resolved snapshot 更新为 `DeepSeek-V4.1-Flash-1017`，请求别名仍为 `deepseek-flash`。

本记录依据公开公告和上述所有者授权，不是官方模型或账户端点查询结果。当前仍处于工程与真实运行前关卡：映射版本跟进尚未交付，最终候选与新鲜运行绑定仍须验证；原两次调用均未使用，真实验收、正式发布和阶段 4 退出尚未完成。

## 决策驱动因素

- 明确批准快照和官方公告之间的变化，避免旧启用记录被静默升级后继续发送。
- 保留请求别名、响应模型校验、原费用授权和最小外发边界。
- 由 Platform 唯一维护机器契约，消费者使用新版本显式确认，历史仍可读取、撤销和结算。

## 选择

### 本次批准及不变边界

- 仅将本次合成真实验收的 `mappingSnapshot` 固定为 `DeepSeek-V4.1-Flash-1017`。请求目标仍是 `https://api.deepseek.com/responses`，请求模型仍是 `deepseek-flash`；官方别名不是客户端可验证的权重锁，不新增快照 API，也不部署模型。
- `allowedResponseModels` 仍为单元素集合 `["deepseek-flash"]`，唯一允许的 `response.model` 精确为 `deepseek-flash`，任何其他值均拒绝。公告中的快照名称不构成将其加入响应白名单的授权；若后续官方证据与此约束冲突，关闭出口、停止并重新评审，不以付费探测请求求证。
- 原受限 Responses 协议保持不变：单次、非流式、无会话、无工具，`reasoning.effort=none`、`tool_choice=none`、`store=false`；不增加协议、外发字段、数据、用途、模型或提供方。
- 本次仍仅为两次串行调用：先单个 Finding 解释；只有解释成功且可信费用结算完成，才可执行所选 Finding PR 摘要。每次最多 USD 0.35、合计 USD 0.70，任一次失败即停；不重试、不替换、不补发、不增加数据或调用。已占用尝试不能因撤销或结算而重新获得。
- ADR-0014 的完整请求 6,000 UTF-8 字节、输出 1,500 Token、调用后输入 8,000 观察阈值、每请求 316,373 microUSD 保守预留、Project/部署 UTC 日 USD 5/20 及可信费用独立结算/未知费用保留规则不变。上下文价格版本仍为 `deepseek-flash-context-peak-usd-2026-10-15`，不借映射更新改变价格、有效期或供应商声明风险接受。

### 最小版本化跟进

目标是由 Platform 新增其拥有的个人启用输入 Schema **`0.4.0`**，表达本 ADR 的映射快照；请求别名和单元素 `allowedResponseModels` 不变。Token/费用限制、有效期、来源证明、批准引用和凭据版本等要求保持原约束。本 ADR 只冻结语义及目标版本，不复制 DTO、Schema 或在 Docs 新建机器契约，不表示该版本已经实现或发布。

保留旧 Schema 文件、旧确认记录、价格/费用历史和已发布迁移。旧映射不得静默升级，也不得作为新真实发送的有效批准；不将历史确认重新解释为 1017 确认。历史读取、撤销和独立费用结算继续按原记录及绑定处理。Web 只提交新版本的显式确认，并消费生产者生成的契约；已登记 Key、已有确认或打开任一开关均不单独授予调用次数。

### 工程、运行及兼容顺序

1. 本 Docs 决策与最小同步合并，Docs `main` CI 成功。
2. Platform 交付生产者 `0.4.0` 输入契约、准入和历史兼容测试，PR 与合并后 `main` CI 成功。
3. Web 更新生成的消费契约和仅接受当前版本的显式确认表单，相关测试、PR 与合并后 `main` CI 成功。
4. Deploy 显式固定最终兼容候选及版本/摘要，完成相关测试、PR 与合并后 `main` CI；旧候选不能因文档批准自动变成新候选。
5. 在发送前重新落实具体运行绑定：所有者、部署、具体 Project、不可变合成 manifest/来源、用途/模板、当前 credentialVersion、启用与价格/预留策略版本、1017 映射快照、有效期、批准引用及两次/费用限额。绑定不得超过所依赖启用、价格和来源有效期；任一变化、过期、撤销或缺失均失败关闭。完成原有身份、权限、Secret、网络、取消回收、原子额度、输出/引用、审计和关闭出口等全部技术关卡。
6. 只有以上工程及新鲜运行关卡全部成立，才可执行原有两次串行合成验收；随后按原条件关闭入口/出口、回滚及恢复验证、发布制品并提交唯一阶段报告。关闭 #43、4H 或阶段 4 仍须全部退出证据及相应 `main` CI。

回滚先关闭入口和真实出口，再回退应用。旧应用不得在未获批准的应用/契约/映射组合下发送新或旧映射请求；必要时保持出口关闭。迁移、数据卷、启用/确认、批次、attempt、用量、费用和审计记录保留，不回写旧 Schema、迁移或历史。

## 备选方案

- 继续沿用旧映射或在后台静默升级：拒绝，与已发现的不一致和显式版本确认冲突。
- 把公告快照名称加入 `response.model` 白名单，或先发探测请求：拒绝，超出本次映射授权及既定两次调用边界。
- 换协议、模型部署、增加数据/调用或重新估价：本次不选择，须另行评审授权。

## 正面影响

以独立决策保存原批准历史，给生产者、Web 和 Deploy 一个最小且可验证的跟进目标；映射变化不会自动扩大响应白名单或消耗剩余调用。

## 负面影响与风险

官方别名及公开声明仍可能变化，客户端不能证明实际权重或不可见服务端计价/处理行为；原数据处理与费用残余风险保留。Accepted 只表示本次语义获批，不证明新契约、候选、运行绑定、真实调用、Release 或阶段退出已完成。

## 验证方式

后续生产者/消费者离线回归须验证：新确认使用 `0.4.0` 和精确 1017 快照；旧映射/旧确认不能产生新真实发送但可读、撤销和结算；任何非 `deepseek-flash` 的响应模型均失败；无运行绑定、关闭/过期/撤销、凭据版本变化时零请求；解释失败或结算未完成时摘要零请求；次数和费用限制不变。最终候选与运行绑定按上述顺序核验，假 HTTP 和文档批准均不能替代两次真实验收证据。

本次仅记录 Docs 语义；跨仓库实现、测试及运行验证结果由各自 CI 和后续验收证据提供，不在此预先声明通过。

## 何时重新评估

官方模型/映射、响应模型证据、协议、上下文、价格、有效期、数据政策或原授权绑定变化，出现异常用量/费用，或需要扩大用途、数据、次数、额度、自动重试、工具或部署范围时，先关闭出口并重新评审，不能花费额外请求探测或自动接受新映射。
