# ADR-0014：个人合成验收的 Token 准入与保守费用预留

- 状态：Accepted；所有者已批准策略调整及有条件的两次合成真实验收；技术关卡和具体批次绑定未完成，运行时真实出口继续关闭
- 日期：2026-10-15
- 决策者：ArchGuard 项目所有者；已分别明确确认策略/残余风险及合成验收次数/费用授权
- 部分替代：[ADR-0010](0010-agent-trust-boundary-and-model-egress.md)、[ADR-0011](0011-deepseek-official-api-egress.md)、[ADR-0012](0012-personal-deepseek-release-scope.md)中个人模式的输入 Token 调用前保证和单请求费用条款；其他信任、数据、协议、授权、日额度及失败边界保留

## 背景

阶段 4 仍未完成真实验收、发布和退出。原个人方案要求发送前证明完整请求输入不超过 8,000 Token，并据此按 8,000 输入、1,500 输出预留 4,200 microUSD。完整请求即使不超过 6,000 UTF-8 字节，也不能证明供应商实际输入计数：请求还涉及托管 Responses 的包装，字节数加固定余量不是其 Token 上界。

截至本决策日，公开[官方 Token 说明](https://api-docs.deepseek.com/quick_start/token_usage/)给出近似字符比例、离线 tokenizer 参考及调用后 usage，未提供足以证明完整 `instructions`、`input`、`text.format` JSON Schema 和托管隐藏包装上界的预发送计数依据。本决策接受这个证据缺口，而不是把估算描述成证明或悄悄换协议。

项目所有者已分别批准本策略调整，以及工程和 CI 全部通过后仅以合成数据串行执行两次真实验收的条件授权。本 ADR 不表示这些条件已满足，也不代替具体 Project、输入清单和凭据版本的运行绑定。

## 决策驱动因素

- 继续使用 DeepSeek 官方托管 API；不部署模型，不增加厂商、SDK、工具或协议。
- 把本地可验证的请求体/输出控制、调用后观察阈值、供应商声明假设和费用授权明确区分。
- 不继续使用失去输入上界前提的 4,200 microUSD 预留，也不改写旧批准、尝试、价格策略或费用历史。
- 即使模型输出、引用、授权或验收失败，可信已发生用量仍须记账；未知结果不自动重试或退款。

## 选择

### 适用范围与不变边界

- 仅调整 ADR-0012 的个人所有者本地部署范围；本次运行授权仅限合成 Finding、Evidence 和 Markdown/纯文本文档。企业/客户数据、多人或公网服务仍受原严格关卡约束。
- 固定 `https://api.deepseek.com/responses`、`deepseek-flash` 和受限 Responses 协议：单次、非流式、无会话、无工具，`reasoning.effort=none`、`tool_choice=none`、`store=false`。不扩展最小外发字段，不用 Chat Completions 绕过本决策。
- [官方模型/价格目录](https://api-docs.deepseek.com/quick_start/pricing/)于 2026-10-15 核对仍将别名映射到 DeepSeek 4.1 Flash。别名不是客户端可验证的权重锁；模型、映射、价格或上下文声明变化时先暂停并重新评审。
- 保留部署/Project 默认关闭、有效个人启用及来源证明、当前可信身份/资源授权、凭据版本、固定网络出口、Schema/业务/引用校验、一次尝试、超时取消、幂等和无正文审计。Agent 不改变 Finding、基线、门禁或 CI 退出码。
- ADR-0012 的未知处理/存储地区、训练/人工复核、日志/缓存与保留风险仍为未知；所有者本次接受该合成验收的残余风险，不宣称零保留或供应商账户级保证。

### 请求体控制与调用后 Token 阈值

- 外发前校验**完整编码 JSON 请求体最多 6,000 UTF-8 字节**，包括固定指令、最小输入、JSON Schema 和全部控制字段；不是只计算业务文本。超限零请求，不以移除安全约束或扩大发送字段补救。
- `max_output_tokens` 固定不超过 1,500；[官方 Responses 参数说明](https://api-docs.deepseek.com/api/create-response/)将其定义为包含可见输出及 reasoning 的输出上限。仍禁用思考并校验 reasoning 为零，不把输出限制误称为输入限制。
- 输入 8,000 Token 改为**调用后验收观察阈值**，不是发送前可证明硬上限。不得宣称 6,000 字节、离线 tokenizer、固定余量或调用后拒绝证明了完整请求输入不超过 8,000 Token，也不能追回已发送的用量。
- 实际输入超过 8,000 时，该请求不得形成成功验收结果，并关闭本批次后续发送；可信且可计价的实际 usage 仍先独立结算，不能因输出/引用/验收失败改记零费用。用量不可信或缺失时保留预留为未知，不自动补发。

### 供应商声明假设与费用预留

- [官方模型列表文档](https://api-docs.deepseek.com/api/list-models/)把 `context_window` 定义为输入与输出合计容量，`deepseek-flash` 的文档示例为 **1,048,576 Token**。这是公开供应商声明/示例，不是本次账户查询或对不可见服务端行为的证明；本方案依赖该声明仍适用于冻结模型及协议。
- 使用经复核、有版本和有效期的美元高峰目录：每百万 Token，输入未命中 USD 0.30、输入命中 USD 0.006、输出 USD 1.20。预留不依赖低峰、赠送余额或缓存命中。
- 保守推算把完整 1,048,576 容量全当作未命中输入，**不扣除**另外预留的 1,500 输出，因此故意高估合计容量：`1,048,576 × 0.30 + 1,500 × 1.20 = 316,372.8 microUSD`。向上取整，每请求预留 **316,373 microUSD（USD 0.316373）**；两次合计 **632,746 microUSD（USD 0.632746）**。
- 个人模式单请求本地费用准入上限由 USD 0.10 调整为 **USD 0.35（350,000 microUSD）**；每 Project 每 UTC 日 **USD 5**、单部署每 UTC 日 **USD 20** 不变。并发及未知结果的预留仍计入额度；任何一层不足、价格/声明依据未知或过期时不发送。
- 这是基于供应商声明和版本化单价的本地保守预留及准入控制，**不是供应商账户强制限费、余额上限或绝对零超支保证**。供应商计数、计价、上下文实施或声明改变可能破坏推算；有异常立即停止后续发送并保留可审计费用事实，不能以本地失败抹去供应商收费。
- 新预留策略及计价校验须使用新的不可变版本，与旧 8,000/4,200 策略区分；不得仅放宽输入校验而沿用旧预留。合法实际 input/output/cache usage 按绑定目录结算，即使超过 8,000 观察阈值也不得因此丢失已知费用。DTO、算法、整数边界和失败码由 Platform Technical Design/契约定义，Docs 不复制实现。

### 两次合成真实验收的条件授权

所有者于 2026-10-15 单独批准：**仅串行两次**，单个 Finding 解释一次、所选 Finding PR 摘要一次，每请求最多 USD 0.35，总授权最多 **USD 0.70（700,000 microUSD）**。这不是日常使用、余额查询、其他模型请求或客户源码的授权。任一次失败立即停批，不自动重试、不并发、不新增请求补齐次数；已占用的唯一尝试不能因费用结算释放而重复使用。

实际执行前必须同时完成：

1. 本 ADR 与同步需求经 Docs PR 合并且 `main` CI 成功；新版本 Platform 提供方、Web 消费及 Deploy 候选的相关工程检查、PR CI 和合并后 `main` CI 全部通过。
2. 完成真实出口所需的数据库/凭据/网络超时与取消回收、身份及 Project 授权、原子额度、输出/引用、审计、关闭出口和回滚的实现及离线回归关卡；确定性假模型或假 HTTP 不能代替获批调用所产生的最终真实证据。
3. 将本次授权写入受控运行记录，绑定所有者、部署、**具体 Project、不可变合成来源/manifest、两种用途及模板、当前 credentialVersion、新预留/价格与模型快照、有效期**和次数/费用上限。有效期不得超过所依赖启用记录、价格目录或来源证明；当前未绑定部分不是通配授权，Key 轮换或任何绑定变化均须重新核验，不能隐式沿用。
4. 确认无聊天中暴露的旧 Key，运行时 Secret/加密存储与网络检查有效，部署及 Project 开关只为该受控验收开启。浏览器不直连模型，不回显或持久化 Key。

执行后验收：核对返回模型、input/output/cache usage、阈值、保守计价、版本引用、traceId 和审计；完成或失败后关闭入口/出口，验证无后续调用。需要供应商实际账单材料时由所有者提供脱敏受控证据，不自动查询账户或余额。

具体绑定、真实调用和验收结果均尚未完成。仅批准本 ADR、合并文档、输入 Key 或显示 Web 入口，均不自动授权绕过上述条件发请求。

### 兼容、发布与回滚

兼容顺序为 Docs 语义冻结 → Samples/Platform 新策略、版本化契约与离线回归 → Web 消费与受控状态 → Deploy 最终候选/获批合成真实验收及发布 → Docs 唯一阶段报告。Scanner Result/Rules 与 Agent Output 既有兼容线不变；不启用 Gateway/Evals，不创建占位或提前阶段报告。

回滚先关闭 Web/Project 入口和真实出口，再回退应用；保留迁移及历史启用、批次、attempt、费用和审计。旧策略记录继续按原绑定读取/结算，不能改写旧迁移或把新费用边界套到历史请求。只支持旧预留策略的应用不得继续发送新策略批次。真实证据、制品、报告和最终 `main` CI 齐全前，#43、4H 及阶段总 Issue 保持开放。

## 备选方案

- 等待覆盖完整托管包装的官方预发送计数证明：仍可在获得证据后重新评审，但不把目前不存在的保证作为已完成事实。
- 仅用字节/字符/tokenizer 估算，并保留 4,200 microUSD：拒绝，费用预留与缺失的输入保证不一致。
- 改协议、换模型、部署模型、增加工具或无限制扩容：本次均不选择，超出已批准范围。
- 只在调用后拒绝超额且宣称未花费：拒绝，无法撤回已发用量，已知费用必须记账。

## 正面影响

将不可证明的输入硬保证改为透明、有限的风险接受；在不扩展数据和协议边界的前提下，以显著更保守的版本化预留支持两次合成验收准备。

## 负面影响与风险

预留远大于常见小请求，减少可用日额度；供应商声明与实际计费仍存在不能由客户端消除的风险。观察阈值只能停止后续调用，不能阻止首个请求在服务端超过 8,000 输入 Token 或撤回已处理数据。本 ADR 的 Accepted 状态不是实现、账户保证、真实验收、发布或阶段关闭证据。

## 验证方式

- 离线/假 HTTP 覆盖完整请求字节边界、输出限制、输入阈值内外、费用取整/并发额度、新旧策略隔离、未知费用保留及无自动重试；实际输入超过 8,000 仍结算可信费用并停止第二次发送。
- 无具体绑定、任一失效/撤销、配置关闭或技术关卡缺失时请求数为零；两次总数、用途、串行、单次/总费用边界不可由前端修改。
- 真实验收仅在上述授权全部生效后执行，保存最小可追溯证据，不保存 Key、账户私密资料、完整请求/原始输出或客户源码。
- 真实验收通过不自动关闭阶段；仍须最终候选回滚、兼容制品、唯一报告、PR 与合并后 `main` CI，且原 `PASS`/`FAIL` 与 CI 退出码不变。

## 何时重新评估

模型/映射/上下文/协议/价格或数据政策变化，出现超阈值/异常费用，取得完整预发送计数依据，或需要新增请求、用途、数据、用户、部署、工具、自动重试或更高额度时，先关闭出口再单独评审与授权。
