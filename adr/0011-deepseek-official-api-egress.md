# ADR-0011：DeepSeek 官方 API 的受限接入与真实外发关卡

- 状态：Accepted；真实外发未获批准
- 日期：2026-09-30
- 决策者：ArchGuard 项目所有者
- 替代：[ADR-0010](0010-agent-trust-boundary-and-model-egress.md)中的首个真实协议及供应商专属数据处理假设；其余信任边界、额度和失败语义继续适用

## 背景

阶段 4D 已有确定性假模型的解释、校验和审计基础，但没有真实模型外发。项目选择由 DeepSeek 官方直接提供 API，不通过第三方推理平台代理。当前 [DeepSeek Responses API](https://api-docs.deepseek.com/guides/responses_api/)与原定协议形状相近，却不保证全部参数同义：不支持的参数可能被静默忽略，`store` 不受支持。官方[磁盘上下文缓存说明](https://api-docs.deepseek.com/guides/kv_cache/)指出缓存默认启用，闲置内容通常在数小时至数天后清理。因此响应中的 `store: false` 不能作为零保留证明。

## 决策驱动因素

- 继续推进解释、摘要和 Web 契约，不把供应商商务审批当成所有开发的阻塞项。
- 不用“OpenAI 兼容”推断数据保留、参数支持、模型版本或价格语义。
- 保留 ADR-0010 的最小外发、三次授权与引用校验、确定性门禁隔离、默认关闭和费用硬上限。

## 选择

### 协议与模型

- 首个真实提供方固定为 DeepSeek 官方，固定 HTTPS 目标 `https://api.deepseek.com/responses`，模型请求名固定为 `deepseek-flash`；不得接受用户输入的 URL、模型名、代理或重定向。官方[模型目录](https://api-docs.deepseek.com/quick_start/pricing/)当前将该别名映射至 4.1 Flash 版本；别名映射会变，须记录请求别名、响应模型标识及批准时的映射快照，映射变更时停止真实调用并复核。
- 适配器仅在 Platform 基础设施层使用 HTTPS/JSON，不把供应商 SDK 或响应对象带入领域或公共 Agent 契约。请求为单次、非流式、无会话；发送版本化 `instructions`、获授权的最小文本 `input`、`text.format` JSON Schema、`max_output_tokens` 不超过 1,500、`reasoning.effort: none`、`tool_choice: none` 和 `store: false`。不发送 `tools`、文件、图片、`user`、`metadata`、`previous_response_id` 或会话 ID；本地仍必须校验完整 Schema 与引用。
- 只允许 `status: completed` 且有合法用量与唯一文本输出的响应进入业务校验。`reasoning`、工具调用、拒绝、截断、非预期模型标识、缺失或异常用量、额外输出、未知字段和非 JSON 输出均失败关闭，不展示原文。
- 不以 `store: false`、无会话或客户端不重复提交推断供应商不缓存、不留日志或不训练；这些只能通过账户级书面材料确认。

### 真实外发审批包

真实网络调用，包括合成数据验收，必须在以下证据齐全、项目所有者批准并记录受控证据编号后才能开启：

1. DeepSeek 官方就本项目 API 账户书面确认合同主体、实际推理与存储地区、下游处理方、输入/输出是否用于训练或人工复核、日志与磁盘上下文缓存的内容范围、隔离、保留和删除期限，以及能否停用缓存或提供等效约束。
2. 项目所有者确认以上条款满足 ADR-0010 的零数据保留或明确记录的等效数据处理约束；若无法满足或材料不覆盖实际账户，真实外发暂停，不以公开帮助页或个人隐私政策替代账户级证明。
3. 运维方确认运行时 Secret 托管、轮换、最小出站防火墙、禁止代理继承和正文日志、固定证书验证与变更监测；不得在仓库、Issue、PR 或审计中贴密钥。
4. 维护版本化美元价格目录和有效期；以高峰、输入全部缓存未命中估价，不能把折扣或缓存命中作为预算前提。官方[价格页](https://api-docs.deepseek.com/quick_start/pricing/)在本决策日列示 `deepseek-flash` 高峰输入未命中 0.30 美元/百万 Token、输出 1.20 美元/百万 Token；上线前须复核。单次 8,000 输入、1,500 输出、0.10 美元，Project 每 UTC 日 5 美元和部署每 UTC 日 20 美元仍是硬上限。

审批记录只写批准人、日期、适用账户/Project、提供方与模型、证据编号、条款版本、地区、价格目录版本和失效条件；保密原件放在受控系统。任一证据缺失、过期或变化时调用前失败关闭。

### 推进与发布关卡

- Docs 冻结本决策后，4D 可在默认关闭和假模型下完成请求、校验、额度及审计基础；真实 DeepSeek 适配器、费用结算和启用验收作为独立的受限外发跟踪项。只有在 4D 的合成范围被明确写入 Issue 验收且其 PR 合并、Platform `main` CI 成功后，4E 才能开始。
- 4E、4F 和 4G 可沿同一版本化契约使用确定性假模型开发和测试，不暗示真实模型已经可用。4H 不得把假模型演示或未获审批的真实调用写成真实外发验收通过；`v0.5.0-agent` 的真实模型发布仍受本 ADR 审批包约束。
- 获批后，先用合成 Finding、Evidence、文档进行真实 API 验收；客户数据启用需再次确认批准范围。启用仍要求部署开关和 Project Maintainer 开关同时打开。回滚先关 Web 入口和 Project 开关，再关模型出口，保留迁移与历史结果。

## 备选方案

- 只替换原协议的 base URL：拒绝；不支持的参数可能被静默忽略，且 `store: false` 不等于零保留。
- 直接以 DeepSeek 公开隐私说明批准客户数据：拒绝；缺少针对本账户的缓存、日志、训练及处理地区证据。
- 为赶进度放宽 ADR-0010 或让模型改变门禁：拒绝。
- 第三方托管 DeepSeek 模型：本决策不采用；会增加处理方与数据链路。

## 正面影响

项目可以独立验证 Agent 契约、界面与安全边界；供应商审批完成后再激活固定的官方模型出口，不影响 Scanner 和质量门禁。

## 负面影响与风险

书面条件可能无法取得，导致真实 API 发布长期暂停。`deepseek-flash` 是别名，模型或价格可能变化；官方默认缓存可能不满足项目要求。不能把合成模型通过的验收描述成真实模型通过。

## 验证方式

用假 HTTP 服务器校验唯一目标、请求字段 allowlist、禁用工具/会话、结构化输出、异常状态、超时、一次尝试、Token/费用预留和日志脱敏。获批后只用合成数据完成一次真实请求、用量与模型标识核对；Web 引用必须由 Platform 重新解析，原有 `PASS`/`FAIL` 完全不变。

## 何时重新评估

DeepSeek 修改模型映射、价格、缓存/训练/日志政策或处理地区；账户级书面条件无法满足；需要新外发字段、工具、自动重试、更多 Token 或更高额度时，均重新评审，不静默扩大范围。
