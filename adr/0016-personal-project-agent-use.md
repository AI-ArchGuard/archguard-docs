# ADR-0016：个人 Project Agent 的日常使用授权与请求

- 状态：Accepted；落实所有者于2026-10-29批准的[完整设计](../docs/superpowers/specs/2026-10-28-stage4-agent-workbench-design.md)，仅批准开发；日常生产者契约、实现和真实验收尚未交付
- 日期：2026-10-29
- 决策依据：所有者要求阶段四全部既定Agent功能可用，并确认“按这版设计实现”；此确认不授予任何真实调用、次数或费用
- 关系：补充[ADR-0012](0012-personal-deepseek-release-scope.md)的个人日常使用路径，沿用[ADR-0010](0010-agent-trust-boundary-and-model-egress.md)/[ADR-0011](0011-deepseek-official-api-egress.md)未被替代的信任边界、[ADR-0013](0013-personal-write-only-credential-management.md)凭据管理、[ADR-0014](0014-personal-token-admission-and-cost-reservation.md)费用策略与[ADR-0015](0015-approved-deepseek-1017-mapping.md)映射要求；不改变旧合成验收授权、失败或费用历史

## 背景

普通Agent请求已能从公开领域接口取得获授权的Finding、扫描/报告、PR修订和文档版本，生成候选引用与不可变最小输入，但只运行假模型/关闭模型。另一路真实执行限定合成Project、来源清单、批次和解释/摘要模板。把页面或部署开关打开，不能让普通请求安全地使用真实API。

阶段四的个人自用结果应是：配置完成后，从普通Finding或PR页面选择已有资源，显式请求解释或所选Finding摘要。用户不需要输入合成模板、来源卷、批次或工程摘要；也不能因此失去权限、来源、输出/引用、费用和审计约束。界面基础改进与这个后端增量分开交付。

## 决策驱动因素

- 复用已实现的最小投影与严格模型边界，避免复制整套合成执行服务。
- 把有界的个人日常授权与一次性的合成退出验收区分，保留真实失败、UNKNOWN及已有预留。
- 让系统提供可验证的资源版本与运行事实，所有者只确认本人有权发送的材料、未核实风险和具体预算；不伪造风险接受或费用授权。

## 选择

### 个人日常授权独立存在

增加独立、版本化、可撤销的个人Project日常使用授权。它绑定专用所有者、部署、Project、用途、数据政策、当前凭据版本、模型/映射、Prompt/输出Schema、价格/预留策略、有效期、最大尝试数及累计授权金额。缺失字段不作为通配值；服务器不能从保存Key、打开页面、旧合成批准或技术日额度推断出授权。

日常模式默认关闭。次数、累计预算和有效期必须由所有者明确提供；当前没有获批值，不能自动填为已同意。每次USD0.35、Project/部署每UTC日USD5/20仍为技术上限，任何授权都受更小的有效上限约束；这些数字不是允许花费的金额。实际金额/次数、数据范围与有效期须在真实启用前具体核对，不通过本ADR或开发测试授予。

风险接受、日常预算授权、Project启用与部署技术开关保留各自可审计的事实；界面可以在一个短设置流程中呈现，不要求用户重复录入系统已知的版本。新授权创建与撤销本身均不调用模型。Key轮换、撤权、过期或模型/价格/协议/部署绑定变化后，旧授权不能自动变成新授权；历史仍可在当前权限下读取和结算。

日常真实操作仅限已配置的个人所有者，并继续遵守Project角色约束；PR摘要还需Maintainer。普通合成/关闭请求原角色语义保留，不借新接口扩大其他用户的真实外发权限。

### 从选定资源生成不可变快照

用户明确选择用途、已完成扫描中的Finding、可信PR修订和已有不可变文档版本。解释固定一个Finding；摘要只覆盖同一兼容PR修订/扫描的选定Finding集合。请求不接受自由Prompt、任意URL、源码上传或外部工具。

Platform通过现有公开模块接口验证资源归属、版本和当前权限，再生成并持久化本次最小输入、候选引用、版本绑定与摘要。重试读取已创建快照，不重新检索或替换成“最新”文档。临发送再次验证当前所有者/Project授权、资源关联、凭据及全部运行绑定；读取结果和解析引用也重新授权。快照存在不等于永久读取或发送权限。

允许的数据沿用ADR-0012：本人有权外发的非敏感材料、Finding规则/严重性/规范消息/必要逻辑实体、直接Evidence类型/关系/必要位置，以及明确选择文档版本中的有界相关片段和不透明候选引用。完整编码JSON仍最多6000 UTF-8字节，输出最多1500 Token；输入8000仍只是调用后阈值。完整文档即使很短也不自动获得发送资格，投影与片段选择不能扩大为传送全部原文。

禁止发送源码及源码片段、完整报告/文档、凭据、成员/审计正文、客户或第三方保密材料、个人敏感信息、其他Project数据和内部标识。数据政策的版本及所有者的选材责任明确展示；自动过滤或字节上限不证明文本必然非敏感。无合格最小投影或超限时零调用，不为“成功”截掉校验约束、无声扩充数据或改协议。

文档中的角色声明、指令、工具调用和外发要求仍是不可信材料。Prompt/候选引用由Platform生成，模型只返回原严格业务Schema；最终引用重新解析到同Project、同输入快照中的真实Evidence或文档版本，不把模型提供的任意位置/链接当作事实。

### 请求、次数、费用与恢复

日常请求使用独立生产者兼容线及与日常授权的确切关联，不复用合成模板ID，也不把旧`SYNTHETIC_ACCEPTANCE`记录升级成个人Project授权。提供方调用仍由后台执行，一个请求最多一次尝试，无自动重试、工具或会话延续。

相同所有者、Project、幂等键和版本化输入返回同一逻辑请求；同键不同内容冲突。服务器提供可恢复查询，Web在丢响应、刷新或重新登录后恢复既有状态，不能生成新键来绕过未知结果。并发重复在事务约束下只取得一次尝试和一份预留；页面加载、状态轮询、引用读取、保存Key和设置变化均为零模型调用。

发送前原子核对日常授权剩余次数/金额、每请求和Project/部署日额度，计入所有在途及UNKNOWN预留。即使实际费用较低或为零，一次已发出的尝试也不能被释放成第二次机会。当前日常授权与合成历史按用途分开追溯，但同一Project/部署技术日额度不能通过换授权或换模式绕过。金额按原始UTC记账日保留；换日不把历史UNKNOWN改成零，也不把同一费用重复记入下一日。授权累计次数/金额不因UTC换日重置。

输出成功与费用结算独立：可信usage按绑定价格结算，输出无效、引用失败、超输入观察阈值或发送后撤权不能把已发生费用改成零；无法证明费用时保留UNKNOWN和预留。任何发送失败、UNKNOWN、引用/费用异常或输入超阈值均停止该日常授权的后续发送，不自动重试或补发。恢复读取、费用核对和修复不产生模型请求；若需再次真实运行，须新授权和全部当前绑定，不能重开旧失败请求、清空历史或通过新授权逃掉旧UNKNOWN在原记账范围占用的额度。撤销不能撤回已发数据，也不能丢失本次完成处理中取得的可信usage。已经固化的UNKNOWN不被迟到回包自动改写；人工对账如需追加更正，必须保留原记录，不自动探测账户或余额。

### 实现边界与兼容顺序

机器契约、DTO、严格上限、状态枚举、错误结构、数据库约束和完整测试清单由Platform生产者唯一维护，Docs不复制JSON Schema。复用已有公开资源接口、快照/候选引用构建、严格结果验证、官方适配器、Secret端口、超时取消和事务账本；确有不同授权/关联语义时新增小适配层，不让领域层依赖模型SDK，也不拆服务。

保留所有已发布迁移；新增日常授权、快照/请求关联和额度约束只能追加迁移。既有Agent Output、Scanner Result/Rules Schema、普通合成接口和受控合成live接口的历史读取、失败关闭与审计语义不变。Agent建议绝不写入Finding、基线、规则、例外、门禁或CI结果。

Docs规范及main CI→Platform独立契约/实现/提供方回归及main CI→Web固定快照/显式操作/状态恢复及main CI→Deploy固定候选与离线Compose。日常模式完整默认关闭路径可以先用假HTTP交付；真实出口须另获具体数据/次数/费用与运行绑定。新的合成退出验收仍独立、仅合成数据，并在新的有效授权下执行；历史失败批次不恢复。本决策不启动Gateway/Evals，也不关闭#43、4H或阶段四。

回滚先关闭日常Web入口、Project和后端出口，再回退兼容应用；保留追加迁移、凭据密文、来源快照、请求、费用、UNKNOWN及审计。回退应用不能被当作撤销已发生费用或延长过期批准。

## 备选方案

- 只把合成验收页美化：能改善展示，但普通Finding/PR仍不能真实使用，不满足已批准目标。
- 解除合成守卫、把模板换成任意资源：混淆数据审批、预算和历史，拒绝。
- 建立新的Agent服务、向量库、通用聊天或工具平台：没有当前需求证据，也超出阶段四；保持模块化单体与原有栈。

## 影响与风险

首次设置后，日常操作直接围绕已选资源进行；历史合成证据不变，新路径可独立验证和关闭。代价是需要新增有界授权与快照/账本关联，离线集成测试必须证明两种模式共享技术总额而不会共享批准。

供应商地区、保留、训练/人工复核仍有未核实事项；最小投影不替代所有者选材判断。本地控制不是供应商硬限费。授权缺失时功能应清楚显示待配置，而不是自动打开出口或假称“真实成功”。

## 验证方式

- 授权缺失、默认关闭、过期/撤销、凭据轮换、额度不足或绑定变化：创建/执行阶段拒绝，假HTTP收到零请求。
- 两个Project的扫描、Finding、PR修订、文档版本混用，以及创建后撤权：不泄漏存在性、材料或引用，零越权外发。
- 只从所选版本形成有界快照；文档更新、提示注入、禁用的源码字段及超6000字节不扩大投影，历史引用仍定位原版本。文本检查不被描述为非敏感证明。
- 同键重复/冲突、并发创建、响应丢失、刷新、进程恢复及取消：一次尝试；未发可明确失败，不能证明未发者保留UNKNOWN，自动重发为零。
- 实际usage与输出/引用成败独立结算；UNKNOWN、失败及超阈值停止授权，旧预留/次数/审计不被重新授权或UTC换日抹掉。
- Web使用普通Finding/PR的选择与明确动作，不手填合成工程ID；无新授权时保持关闭，不对Key作有效性、余额或账户探测。
- 原合成回归、旧批次状态、门禁PASS/FAIL与CI退出码不变；代码、API、离线Compose、真实调用和发布各自有当前版本证据。

## 何时重新评估

需要扩大数据、用户、部署、金额技术上限、模型/协议、重试/工具能力，或无法复用现有授权/费用不变量时，先关闭该路径并重新评审。供应商依据失效或出现未知实际费用时，不以新界面或旧批准继续发送。
