## 执行环境与方式

本地端到端验收在 Windows、Docker Compose、Java 21 和 Microsoft Edge 环境执行。使用的主要命令为：

```text
./mvnw --batch-mode --no-transfer-progress verify
npm run check
npm run check:api
npm run test:e2e
npm audit
docker build ...
docker compose --env-file .local/runtime.env config
docker compose --env-file .local/runtime.env up --build
```

本地凭据由 Deploy 启动脚本随机生成并只写入被忽略的 `.local/`；报告未记录凭据值。

- PostgreSQL 是任务和治理数据事实来源；OIDC、角色隐藏式 `404`、审计、traceId 和结构化错误已验证。
- Scanner `v0.2.1`、Platform `v0.3.0`、Web `v0.1.0` 和 Deploy `v0.3.0` 均可追踪，PR CI、合并后 `main` CI 与发布工作流成功。
- 干净 Compose 可以一条命令启动，完整用户旅程、正常与违规扫描、取消、恢复、处置和清理均通过。

阶段 2 的产品与工程退出条件全部满足，结论为 Passed / Closed。阶段 3 尚未启用，只可进入范围评审。

## 已知限制

- Repository 仅支持部署者预先挂载的本地只读目录，不支持 ZIP 上传、Git clone、Webhook 或 PR/CI 门禁。
- Finding 处置不跨扫描自动继承，也不支持到期、基线、新旧问题分类、趋势或通知。
- Scanner 仍是 Java-first 的受限静态分析，不执行 Maven、不解析传递依赖或完整运行时 Spring 语义。
- 阶段 2 不向远程 Registry 发布 ArchGuard 容器；Deploy 从固定源码 tag 构建本地镜像，因此本地 image ID 不作为跨主机供应链 digest。远程镜像、签名和多环境发布属于后续生产化范围。
- GitHub Issues 已按切片关闭；由于当前凭据缺少 Projects v2 `project` / `read:project` scope，Project #2 的条目与状态字段无法由自动化更新。这不影响产品验收，但需由具备权限的维护者补录看板状态。
