# 测试策略与质量门禁

## 测试金字塔

| 类型 | 目的 | 要求 |
|---|---|---|
| 单元测试 | 领域规则、算法、错误路径 | 快、确定、无外部依赖 |
| 模块测试 | 模块公开接口和边界 | 验证事务与权限 |
| 集成测试 | PostgreSQL、消息、Git、MCP | 使用Testcontainers或真实兼容实现 |
| 契约测试 | REST、事件、Scanner、MCP Schema | 跨仓库发布前执行 |
| 端到端测试 | 核心用户旅程 | 少量、稳定、只覆盖关键路径 |
| 性能测试 | 扫描、网关和查询容量 | 固定数据集，可重复比较 |
| Agent评估 | 正确性、工具、安全和成本 | 版本化数据集，CI回归 |

覆盖率不是唯一目标；新增/修改核心领域逻辑原则上应有分支测试。禁止为了数字测试Getter或框架代码。

## PR必过门禁

- 构建、格式化、lint通过；
- 单元和相关集成测试通过；
- 架构规则测试通过；
- 高危依赖/镜像漏洞为零，或有带期限的豁免；
- 无密钥泄漏；
- 数据迁移通过空库和上一版本升级测试；
- 对外契约无未声明破坏性变化；
- 功能、设计、ADR和运行文档已同步。

## Agent专属门禁

- 固定评估集任务成功率不得低于基线；
- 高风险误报、越权工具调用和敏感信息泄漏为零；
- 平均成本、P95延迟和工具调用次数不得超过预算；
- 模型/Prompt变化必须保存对比报告；
- AI评论只能作为建议，确定性规则才允许阻断合并。

## 建议初始指标

这些是起始门槛，获得真实基线后再调整：

- 核心API集成测试100%通过；
- Scanner固定样例准确率100%；
- MCP未授权请求阻断率100%；
- PR评审最多输出5条高置信建议；
- 服务健康检查30秒内稳定；
- 所有外部调用有超时。
