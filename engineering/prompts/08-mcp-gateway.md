# 阶段 8：Go MCP Gateway

## 阶段目标

在 `archguard-mcp-gateway` 建立最小 Go MCP 网关，以默认拒绝和最小权限提供只读工具，并实现身份传播、限流、审计、可观测和安全退出。

## 输入与范围

- 必需：Feature Spec、Technical Design、工具目录、身份与授权模型。
- 相关契约：Platform API、Scanner 结果、ADR 搜索和 CI 查询。
- 首批工具仅限：搜索代码、读取文件、查询依赖、查询违规、搜索 ADR、查询 CI 状态。
- 非目标：写仓库、执行任意 Shell、自动合并、直接访问业务数据库和无限制代理循环。

## 开始前检查

1. 确认 Go 版本和 MCP 协议/SDK 的受支持版本。
2. 记录每个依赖的用途、许可证、维护状态和替代方案。
3. 为每个工具定义调用者、数据源、权限、参数、输出、超时和审计字段。
4. 威胁建模：路径穿越、命令注入、提示注入、跨租户访问、SSRF、超大响应和循环调用。
5. 明确上游身份声明的签名、信任边界和失败策略。

## 执行流程

### 8A：服务骨架

1. 初始化 Go module，固定依赖并提供可复现构建。
2. 分离 transport、catalog、authorization、application 和 adapters。
3. 实现配置加载、结构化日志、健康检查和优雅关闭。
4. 所有外部 I/O 接受 `context.Context`，设置超时并传播取消。
5. 每个 Goroutine 都必须有所有者、停止条件和回收路径。

### 8B：工具目录和 Schema

1. 工具名、用途和参数保持窄而明确。
2. 参数使用严格 Schema、长度/枚举/路径白名单，不接受任意命令。
3. 输出包含稳定版本、结果、证据和可诊断错误。
4. 工具声明和执行共用同一授权元数据。
5. 大结果分页、截断或返回引用，不输出完整仓库。

### 8C：身份、授权与限制

1. 每次调用绑定 actor、tenant、project、repository 和 trace。
2. 默认拒绝；授权失败不得调用下游。
3. 读写工具分离，本阶段不得注册写工具。
4. 设置单次超时、响应大小、并发、速率和会话总调用上限。
5. 审计记录请求摘要、授权决策、工具、结果状态和耗时，不记录凭据或完整源码。

### 8D：适配器与可观测

1. 仅通过公开 API 或版本化契约访问下游。
2. 对下游错误分类并保留 cause，不记录后吞掉。
3. 使用 OpenTelemetry 关联入口、授权和下游调用。
4. 指标覆盖调用量、拒绝、限流、超时、错误、延迟和活动会话。
5. 实现就绪/存活检查和关闭期间拒绝新请求。

## 交付物

- Go 服务、工具目录和版本化 Schema。
- 六个只读工具及其授权策略。
- 限流、超时、审计、OpenTelemetry、健康检查和优雅关闭。
- 安全测试、race test、benchmark 和 Runbook。

## 验证

1. `gofmt`、`go vet ./...`、`go test ./...` 和 `go test -race ./...`。
2. 未授权、跨租户、路径穿越、命令注入、SSRF 和超限测试。
3. 下游超时后 Context 取消和 Goroutine 回收测试。
4. 并发限流、优雅关闭和重复调用测试。
5. Benchmark 记录固定数据与环境。
6. 确认每次调用可通过 traceId 和审计记录关联。

## 停止条件

MCP SDK 许可证或版本不清楚、身份信任边界未决定、工具需要写权限或任意 Shell、下游缺少资源归属校验时停止。

## 退出条件

未授权调用全部拒绝；工具只读且参数严格；超时可取消；race test 无竞争；每次调用可审计。
