# 阶段 9：Evals 基线与安全中心

## 阶段目标

在 `archguard-evals` 建立与模型供应商和 Agent 框架解耦的版本化数据集、评分器、基线报告和安全回归门禁，为 AI 功能开发提供先验验收标准。

## 输入与范围

- 必需：评估 Technical Design、数据分类和评分规则。
- 输入契约：Scanner 结果、MCP Tool Schema、预期 Agent 输出 Schema。
- 非目标：实现生产 Agent、把主观 LLM 评分作为唯一真相、使用真实客户源码或个人数据。

## 开始前检查

1. 决定实现语言和运行器，并记录依赖、许可证与替代方案。
2. 建立评估分类：任务成功、工具选择、参数、引用、误报、成本、延迟、安全和循环。
3. 定义数据集 Schema、版本规则、样例 ID 和变更审查规则。
4. 明确确定性评分、人工标注和模型评分各自适用范围。
5. 建立脱敏标准和禁止进入数据集的信息清单。

## 执行流程

### 9A：数据集与黄金答案

1. 建立至少 20 个覆盖正常、边界、失败和对抗场景的合成样例。
2. 每个样例包含输入、允许工具、禁止行为、预期证据、黄金结果和标签。
3. 固定引用位置和工具参数的验证规则。
4. 对顺序不敏感的输出使用规范化比较。
5. 数据集修改必须提升版本并记录原因。

### 9B：评分器

1. 优先使用确定性评分：Schema、工具名、参数、权限、引用和预算。
2. 对文本质量使用窄范围规则或带版本的辅助评分器。
3. 输出总分前保留分项结果和失败步骤。
4. 定义通过阈值、零容忍安全项和统计波动范围。
5. 评分器本身需要单元测试和已知好/坏样例。

### 9C：运行器和报告

1. 固定候选模型、Prompt、工具、数据集和评分器版本。
2. 记录随机性参数、重试、Token、延迟、调用次数和错误。
3. 支持候选与基线并行比较。
4. 报告按样例和指标展示改善、退化及置信信息。
5. 不隐藏失败或用自动重试覆盖首次失败事实。
6. 将本地临时报告与可提交的脱敏摘要分离。

### 9D：安全中心

1. 覆盖提示注入、间接注入、越权工具、跨项目访问、敏感信息泄漏和无限循环。
2. 高风险越权与泄漏必须为零。
3. 为循环次数、总时长、Token、并发和费用建立硬限制测试。
4. 生产失败只有脱敏和批准后才能转为回归样例。
5. 严重安全退化在 CI 中阻断，普通质量波动进入报告。

## 交付物

- 数据集 Schema、20 个以上版本化样例和黄金答案。
- 确定性评分器、运行器、测试和基线报告。
- 安全回归集、预算配置和 CI 比较规则。
- 数据治理、复现和失败分析说明。

## 验证

1. 在相同输入和固定配置下重复运行，确认确定性评分一致。
2. 对评分器运行正例、反例和边界单元测试。
3. 验证报告能定位到样例、步骤、工具和具体失败原因。
4. 执行越权、泄漏、注入和循环安全集。
5. 检查数据集无真实源码、个人数据和凭据。
6. 从干净环境按 README 重现基线。

## 停止条件

数据集来源或许可证不明、评分标准无法解释、真实敏感数据未脱敏、零容忍安全项无法自动检测时停止。

## 退出条件

评估可重复运行，基线有版本，失败可定位，安全零容忍项可阻断，并能作为阶段 10 的实施门禁。
