# 阶段 13：求职交付审计

## 阶段目标

以高级后端/架构岗位面试官和新维护者视角审计整个 ArchGuard 工作区，验证所有展示结论都有可复现证据。先只读审计，再将 P0 修复拆成独立任务，最后完成发布准备审查。

## 输入与范围

- 输入：七仓库目标版本、兼容矩阵、发布记录和演示环境。
- 审计覆盖 README、需求、架构、ADR、代码、测试、CI、部署、性能、安全、Issue 和 PR 历史。
- 非目标：新增大型功能、重写架构、为展示指标伪造数据。
- 只读审计不授权修改；P0 修复必须使用明确的修复任务和范围。

## 开始前检查

1. 记录七个仓库分支、提交、标签、工作树和远程 CI 状态。
2. 确认待审计版本与部署环境实际运行版本一致。
3. 建立证据目录，区分本地、CI、Staging 和 Production 结果。
4. 定义 P0/P1/P2：
   - P0：阻止构建、演示、基本安全或真实性。
   - P1：显著降低可信度、维护性或关键能力。
   - P2：改进体验、覆盖和表达。
5. 不覆盖用户修改，不在审计阶段顺带修复。

## 执行流程

### 13A：只读审计

逐项检查：

1. **理解性**：陌生开发者能否找到入口、职责、非职责和启动路径。
2. **需求**：核心功能是否有 Feature Spec、验收标准和非目标。
3. **架构**：C4、仓库边界、模块边界和 ADR 是否与实现一致。
4. **契约**：API、Scanner、MCP 和事件是否版本化且有兼容测试。
5. **代码质量**：领域边界、错误处理、事务、Context、并发和依赖说明。
6. **测试可信度**：是否覆盖错误路径，是否存在删除测试、弱断言或伪造结果。
7. **CI/CD**：必需检查、权限、依赖锁定、制品来源和分支保护。
8. **安全**：Secret、权限、源码处理、提示注入、供应链和公开端口。
9. **可观测**：traceId、日志、指标、告警、Dashboard 和 Runbook。
10. **部署**：新机器启动、健康检查、备份恢复、兼容矩阵和回滚。
11. **性能/Evals**：结果能否用脚本、数据集和环境信息复现。
12. **作品集表达**：简历数字、架构故事和演示陈述是否能追溯到证据。

每个发现记录位置、证据、影响、严重级别、建议和验证方式；未知项不得判断为通过。

### 13B：P0 修复

1. 用户确认审计结果后，为每个 P0 建立独立 Issue。
2. 每次只修一个明确问题，按正常需求、设计和测试流程执行。
3. 修复后重跑最小相关测试和受影响仓库完整质量检查。
4. 跨仓库修复记录版本、顺序和回滚。
5. 不在 P0 修复中夹带 P1/P2 重构。

### 13C：最终发布审查

1. 从干净环境克隆并按 README 启动核心演示。
2. 在 30 分钟内完成登录/项目/仓库/扫描/结果/PR 或 MCP 核心旅程。
3. 对照发布清单检查 CI、版本、变更日志、迁移、备份和监控。
4. 验证所有简历与作品集指标的原始报告或脚本。
5. 记录已知限制，避免将未实现或未验证能力描述为已完成。
6. 输出最终发布建议：Go、Conditional Go 或 No-Go。

## 交付物

- 按 P0/P1/P2 排序的审计报告和证据矩阵。
- P0 独立 Issue、修复记录和复验结果。
- P1/P2 路线图和负责人/期限建议。
- 干净环境演示记录、发布清单和最终 Go/No-Go 决定。

## 验证

1. 七仓库从干净检出运行各自完整质量检查。
2. 跨仓库契约、端到端、Agent 安全和部署 Smoke Test。
3. 实际执行备份恢复和回滚演练。
4. 重新运行性能与 Evals 脚本，核对报告中的数字。
5. 全工作区 Secret、许可证、依赖和公开端口检查。
6. README 链接和 30 分钟演示流程复验。

## 停止条件

审计版本不明确、工作树包含无法归属的修改、证据缺失、需要生产写权限或 P0 修复范围会扩大为新功能时停止。

## 退出条件

所有 P0 已关闭并复验，P1/P2 有明确计划，核心演示可复现，所有对外声明有证据，发布决定和已知限制已记录。
