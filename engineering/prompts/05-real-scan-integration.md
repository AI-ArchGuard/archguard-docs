# 阶段 5：真实扫描集成

## 阶段目标

连接 `archguard-platform`、`archguard-scanner` 和 `archguard-samples`，用版本化契约完成异步扫描、可靠状态更新、临时源码清理和端到端验证。

## 输入与范围

- 必需：跨仓库 Feature Spec、Technical Design、契约文档和兼容计划。
- 记录三个仓库的 `<baseline-commit>` 与目标版本。
- 非目标：Kafka、GitHub Webhook、AI 解释和自动代码修改。
- 当前优先使用数据库任务队列；不得因“展示技术”引入消息中间件。

## 开始前检查

1. 分别运行 Platform 和 Scanner 的完整质量检查。
2. 固定 Scanner 契约版本和一个可公开的 Samples 提交。
3. 明确调用方式、认证、超时、最大输入、失败分类和取消语义。
4. 画出创建任务、领取租约、执行扫描、保存结果和清理源码的时序图。
5. 明确源码临时目录、所有者、保留时间和异常退出后的清理策略。

## 执行流程

### 5A：契约与兼容

1. Platform 只依赖 Scanner 公开 Schema，不导入内部类。
2. 明确支持的契约版本范围、未知字段、错误码和破坏性变更处理。
3. 为请求、结果和错误建立跨仓库契约测试。
4. 在 Deploy 兼容矩阵中预留 Platform/Scanner/Samples 版本关系。

### 5B：异步任务执行

1. HTTP 请求只创建任务，不占用线程等待扫描完成。
2. 定义任务领取、租约续期、超时、取消和终态写入规则。
3. 使用数据库条件更新或等价机制避免两个 Worker 同时拥有任务。
4. 设置有限重试、指数退避、最大执行时长和不可重试错误分类。
5. 结果写入必须幂等；重复回调或重复执行不得产生重复违规。
6. 失败保留可诊断摘要，不保存完整源码或凭据。

### 5C：源码处理与适配

1. 使用白名单参数调用 Git/Scanner，不拼接任意 Shell。
2. 临时目录必须隔离、限制大小并在成功、失败、取消后清理。
3. Scanner Adapter 传播 traceId、scanJobId、契约版本和超时。
4. 清理失败需要指标、日志和补偿任务。
5. 使用固定 Samples 工程验证正常和违规结果。

### 5D：可观测与端到端

1. 指标覆盖队列长度、等待时间、扫描耗时、成功率、重试、租约过期和清理失败。
2. 日志可按 traceId、projectId、repositoryId、scanJobId 关联。
3. 测试完整用户旅程和重复、超时、崩溃、无权限、解析失败路径。
4. 更新运行手册、契约版本、兼容矩阵和回滚步骤。

## 交付物

- 版本化跨仓库契约及契约测试。
- 数据库任务队列 Worker、租约、重试和幂等结果实现。
- Scanner Adapter、临时源码管理和端到端测试。
- 兼容矩阵、指标、Dashboard/Runbook 入口和发布顺序。

## 验证

1. Platform、Scanner 各自完整质量检查。
2. 契约提供者和消费者测试。
3. 固定样例的成功、违规、重复请求和失败恢复测试。
4. Worker 崩溃、租约过期、Scanner 超时和清理失败的故障测试。
5. 并发提交相同幂等键，确认只产生一份业务结果。
6. 检查临时源码最终被删除，日志无凭据和完整源码。

## 兼容与回滚

发布顺序：契约兼容版本 → Scanner → Platform → Samples/Deploy 记录。回滚优先回退 Platform Adapter 或 Scanner 制品，不依赖数据库 Schema 回退；破坏性契约必须使用新版本并行过渡。

## 停止条件

契约所有者、源码保留规则、重试边界、部署拓扑或身份传播未明确时停止。

## 退出条件

固定样例可被真实扫描；重复执行不重复写入；失败可诊断和恢复；临时源码可验证清理。
