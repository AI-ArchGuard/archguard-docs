# 阶段 4：Java Scanner MVP

## 阶段目标

只修改 `archguard-scanner`、`archguard-samples` 的必要合成夹具及契约文档，实现确定、可重复的 Java 依赖分析和首批架构规则。

## 输入与范围

- Feature Spec 和 Scanner Technical Design。
- ADR：确定性规则优先、Scanner 独立契约。
- 非目标：LLM、Platform 内部类、远程仓库克隆、PR 评论、全语言支持。

## 开始前检查

1. 核对 Scanner 仓库状态、Java 版本和构建系统。
2. 定义输入规模、支持的 Java 语法/字节码范围和明确不支持项。
3. 比较 JavaParser、ASM、ArchUnit 及标准 JDK 能力，记录依赖理由和许可证。
4. 定义 ScanRequest/ScanResult Schema 的所有者、版本格式和兼容策略。
5. 准备正常、直接违规、多跳循环、重复边和解析失败的最小合成样例。

## 执行流程

### 4A：版本化契约

1. 定义请求标识、Schema 版本、源码根、规则配置和限制参数。
2. 定义结果状态、违规类型、证据位置、错误码、统计和耗时。
3. 明确路径规范化、字符编码、排序规则和可选字段语义。
4. 使用 JSON Schema 或等价机器可验证形式发布契约。
5. 建立向后兼容和未知字段处理测试。

### 4B：分析管线

1. 将输入验证、文件发现、解析、依赖抽取、图构建、规则执行和序列化分层。
2. 对文件数、文件大小、目录深度和总执行时间设置上限。
3. 解析错误保留最小定位信息，不输出不必要的源码内容。
4. 依赖图去重，节点和结果使用稳定排序。
5. 禁止解析器层依赖 Platform 业务模型。

### 4C：确定性规则

1. 实现禁止包依赖，覆盖精确匹配和边界条件。
2. 实现循环依赖，说明采用的图算法和复杂度。
3. 为直接循环、多跳循环、自环和无环图编写黄金测试。
4. 同一输入重复运行必须得到字节级或规范化后完全一致的结果。
5. 未知规则、错误配置和部分解析失败必须有明确行为。

### 4D：性能基线

1. 固定数据集、硬件/运行环境和测量命令。
2. 记录文件数、节点数、边数、耗时和峰值内存。
3. 不设置无数据依据的承诺；先保存基线再定义预算。
4. 报告必须可复现并保存原始结果摘要。

## 交付物

- 版本化 ScanRequest/ScanResult Schema。
- 分层扫描管线、依赖图和两类确定性规则。
- 合成样例、黄金测试、错误码文档和性能基线。
- README 中的构建、执行和限制说明。

## 验证

1. 完整 Java 构建、格式、静态和架构检查。
2. 正常、直接违规、多跳循环、自环、解析失败和超限测试。
3. 契约序列化、兼容和稳定排序测试。
4. 固定样例重复运行并比较结果。
5. 性能脚本至少运行一次并保存环境信息。
6. Secret、路径穿越和敏感源码日志检查。

## 停止条件

契约版本策略未确定、解析库许可证不可接受、输入限制缺失或规则结果无法做到确定性时停止。

## 退出条件

固定样例结果完全稳定，错误可定位，契约版本明确，性能基线可复现，且 Scanner 不依赖 Platform 内部实现。
