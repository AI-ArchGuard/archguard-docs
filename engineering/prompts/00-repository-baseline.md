# 阶段 0：仓库基线

## 阶段目标

在不实现业务功能的前提下，为七个独立仓库建立一致、可审查、可运行的治理基线，使后续开发具备明确边界、统一协作方式和最小 CI 证据。

## 输入与范围

- 工作区：`<workspace-path>`
- Issue：`<issue-number>`
- 目标版本：`<target-version>`
- 允许修改：七个 ArchGuard 仓库和必要的 `archguard-docs` 规范。
- 禁止修改：外层工作区不得初始化为 Git 仓库；不得实现业务代码。
- 不执行提交、推送、分支保护或项目看板写操作，除非任务明确授权。

## 开始前检查

1. 确认七个仓库名称、绝对路径、`origin`、默认分支和独立 `.git`。
2. 检查每个工作树，记录已有文件和用户修改。
3. 阅读工作区及已有仓库级规则，建立“已有/缺失/冲突”矩阵。
4. 检查 MCP 仓库名称没有末尾连字符。
5. 记录当前许可证、CI、分支保护、Issue、PR 模板和项目看板状态。

## 执行流程

### 0A：规范事实来源

1. 在 `archguard-docs` 建立治理、流程、工程、安全、质量和发布规范入口。
2. 安装 Feature Spec、Technical Design、ADR、PR 和 Postmortem 模板。
3. 建立 product、requirements、architecture、adr、runbooks、reports 目录。
4. 确认 README 能从入口导航到所有规范。

### 0B：仓库治理文件

逐仓库建立：

- 准确的 README：职责、非职责、依赖方向、状态、本地验证命令。
- 仓库级 `AGENTS.md`：继承统一规则并增加语言、边界和命令。
- `CONTRIBUTING.md`、`SECURITY.md`、`CHANGELOG.md`。
- `.editorconfig`、语言对应 `.gitignore`。
- PR 模板和功能/缺陷 Issue Form。
- 只验证现有基线的最小 CI，不声明尚不存在的构建已通过。

### 0C：许可证和远程治理建议

1. 比较 Apache-2.0、MIT 和暂不授权三种方案，记录专利条款、作品集展示和第三方依赖影响。
2. 许可证未决定时只提交建议，不擅自创建 LICENSE。
3. 输出默认分支保护建议：PR、必需状态检查、禁止强推和删除、分支必须最新。
4. 输出跨仓库项目看板及 M0–M9 里程碑配置清单。
5. 远程配置必须等初始提交和 CI 状态出现后再执行。

## 交付物

- 七仓库基线文件清单及职责矩阵。
- 缺失项、许可证建议、远程治理待办清单。
- 每个仓库可独立提交的变更集合。
- M0 初始化验收报告。

## 验证

1. 检查外层目录没有 `.git`。
2. 核对七个 `origin` 和仓库名称。
3. 检查必需文件、Markdown 链接、YAML 结构和空白错误。
4. 对新增文件执行常见 Secret 模式扫描。
5. 能运行的 CI/格式检查必须实际运行；空仓库没有业务测试时明确说明。
6. 确认七个 README 的职责、非职责和依赖方向不冲突。

## 停止条件

发现已有未提交修改发生路径冲突、远程地址不符、仓库身份不明、许可证需要所有者决策或任务要求外部写操作但未授权时停止。

## 退出条件

七仓库基线完整、本地检查通过、未包含敏感数据、远程治理待办明确，并且每个仓库可以分别审查和回滚。
