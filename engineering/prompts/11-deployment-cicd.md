# 阶段 11：部署与 CI/CD

## 阶段目标

在 `archguard-deploy` 建立可重复的本地运行、持续集成、制品发布和公开演示环境方案；配置与 Secret 分离，并证明备份、恢复和回滚可执行。

## 输入与范围

- 必需：部署 Technical Design、环境矩阵、服务版本和兼容矩阵。
- 允许修改：Deploy、各仓库必要的 CI/镜像文件和运行文档。
- 非目标：本阶段不使用 Kubernetes；不开放数据库、Redis 或内部服务端口；不保存真实客户源码。
- 生产发布、云资源创建、域名和 Secret 写入必须有明确授权。

## 开始前检查

1. 记录 Platform、Scanner、Gateway 的构建方式、健康端点、端口和资源需求。
2. 定义 Local、CI、Staging、Production 的差异和允许数据。
3. 固定各制品版本，禁止使用未说明的 `latest`。
4. 威胁建模网络、镜像、Secret、供应链、备份和管理入口。
5. 确认运行环境、预算、域名、证书和回滚责任。

## 执行流程

### 11A：本地 Docker Compose

1. 为服务、PostgreSQL 和必要依赖定义私有网络。
2. 只向主机暴露明确需要的入口；数据库和内部端口仅容器网络可见。
3. 镜像使用多阶段构建、固定基础镜像、非 root 用户和只读/最小文件权限。
4. 配置健康检查、启动依赖、资源限制、持久卷和优雅关闭。
5. 提供无敏感值的 `.env.example`，真实 Secret 不进入 Git。
6. README 提供启动、状态、日志、停止和清理命令。

### 11B：持续集成

1. 各仓库执行格式、lint、单元、集成、架构和契约测试。
2. 增加依赖、Secret、SAST 和适用的镜像扫描。
3. Action 固定到不可变提交并使用最小 `GITHUB_TOKEN` 权限。
4. 缓存不得包含凭据，来自 Fork 的 PR 不接触发布 Secret。
5. 保存必要的测试和扫描报告，设置合理保留期。
6. CI 状态名称稳定，供默认分支保护引用。

### 11C：制品与 Staging

1. 制品使用不可变版本和来源提交标识。
2. 生成 SBOM，记录镜像摘要和依赖扫描结果。
3. 按兼容矩阵部署 Staging，运行数据库迁移、健康检查和核心 Smoke Test。
4. 只有 Staging 证据通过后才能晋级同一制品，禁止重新构建生产镜像。
5. 失败时保持上一稳定版本并保存诊断证据。

### 11D：Production、备份与运行

1. 公网只开放 80/443 和必要且受限的管理入口。
2. 配置 TLS、限流、日志、指标、Dashboard 和可操作告警。
3. 使用合成或脱敏数据，不保留真实客户源码。
4. 实际执行数据库备份和隔离环境恢复。
5. 发布后验证登录、创建项目、扫描和查询，并观察错误率、延迟和资源至少约定时间。
6. 更新发布记录、兼容矩阵和已知限制。

## 交付物

- Compose、镜像构建、环境配置示例和本地运行说明。
- CI 工作流、安全扫描、SBOM 和制品发布流程。
- Staging/Production 部署方案、兼容矩阵和 Smoke Test。
- 备份恢复脚本、Runbook、监控和回滚步骤。

## 验证

1. `docker compose config` 和全新机器/干净环境启动测试。
2. 健康、就绪、服务依赖和优雅关闭测试。
3. 非 root、端口暴露、文件权限和 Secret 扫描。
4. 各仓库 CI 与跨仓库契约测试。
5. Staging Smoke Test 和失败部署回滚。
6. 备份后在隔离环境实际恢复并校验数据。
7. 检查 Production 使用与 Staging 相同的制品摘要。

## 兼容与回滚

默认顺序：兼容数据库迁移 → Scanner/Gateway → Platform → 外部入口。回滚顺序相反；数据库使用 Expand/Contract，应用回滚不依赖 Schema 回退。

## 停止条件

缺少 Secret 管理、镜像来源不明、数据库端口需要公网暴露、备份无法恢复或 Production 写操作未授权时停止。

## 退出条件

新机器可按 README 启动；CI 证据完整；制品可追溯；备份可恢复；部署失败能保持上一稳定版本。
