# 安全与可观测规范

## 威胁边界

主要资产：源代码、仓库Token、用户身份、ADR、模型输入输出、工具权限和审计日志。

主要威胁：越权仓库访问、Webhook重放、Token泄漏、路径穿越、命令注入、提示注入、恶意依赖、租户数据串读、工具无限循环。

## 安全基线

- GitHub App使用最小权限和短期Token；验证Webhook签名与时间窗口。
- Secret只进入Secret Manager或部署环境，不写入Git、镜像和日志。
- 上传、Git路径和命令参数使用白名单；禁止拼接Shell。
- 对象和查询必须同时校验身份、组织、项目与资源归属。
- 源码默认临时处理，明确清理机制；日志不得保存完整源码。
- 依赖锁定、自动更新、SCA、镜像扫描和Secret扫描进入CI。
- 高风险MCP工具要求人工批准，审批与执行绑定同一不可变请求摘要。

## 可观测标准

每个请求/任务携带 `traceId`、`requestId`、`actorId`、`projectId`；不得记录Token和敏感源码。

关键指标：

- HTTP QPS、错误率、P50/P95/P99；
- 扫描队列长度、耗时、成功率、重试和死信；
- MCP调用量、拒绝率、超时率、工具级错误率；
- 模型Token、费用、延迟、评估分数；
- 数据库连接池、慢查询、磁盘和备份状态。

告警必须可操作，包含影响、可能原因、Dashboard和Runbook链接。禁止对每个异常堆栈直接告警。
