# 项目治理与职责

## 项目目标

构建可运行、可测试、可部署、可解释的AI架构治理平台，以项目演进记录证明工程和架构能力。当前不以商业化、用户增长或多语言全覆盖为目标。

## 决策原则

优先级从高到低：正确性、安全性、可维护性、可观测性、性能、开发速度、技术新颖性。

## 文档分级

| 变更 | 必需文档 |
|---|---|
| 小型缺陷 | Issue、测试、PR说明 |
| 普通功能 | Feature Spec、测试计划、PR说明 |
| 跨模块功能 | Feature Spec、Technical Design、ADR（如有决策） |
| 跨仓库/协议变更 | 上述全部，加兼容与发布计划 |
| 安全/数据变更 | 威胁分析、数据分类、回滚和审计方案 |

## 阶段关卡

- Idea：问题与用户价值清楚。
- Ready：验收标准、非目标、风险和依赖清楚。
- In Development：分支已创建，测试策略确定。
- In Review：代码、测试、文档和迁移完整。
- Ready to Release：质量门禁通过，回滚方案有效。
- Done：已部署、健康检查通过、版本和变更日志已更新。

## RACI（个人项目简化版）

| 活动 | 执行 | 审核证据 |
|---|---|---|
| 需求 | 开发者 | Feature Spec与验收标准 |
| 架构 | 开发者 | ADR、C4图、取舍说明 |
| 开发 | 开发者/Codex | Commit、测试、静态检查 |
| 质量 | 自动化CI | 报告和门禁 |
| 发布 | 开发者 | Release清单、健康检查 |
| 复盘 | 开发者 | Postmortem与改进Issue |

## 版本策略

- 对外API和跨仓库契约使用语义化版本。
- 开发期从 `0.x.y` 开始；破坏性修改提升次版本并提供迁移说明。
- 发布标签格式：`vMAJOR.MINOR.PATCH`。
- 七仓库不强制相同版本；`archguard-deploy`记录兼容版本矩阵。
