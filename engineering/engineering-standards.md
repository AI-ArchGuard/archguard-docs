# 工程约定与限制

## Java

- 使用受支持的LTS JDK，构建中固定版本。
- 包按业务模块组织；模块内采用 `api/application/domain/infrastructure`。
- 领域对象保持业务不变量，不把所有逻辑放入Service。
- 构造器注入；禁止字段注入和全局可变状态。
- 应用层定义事务；禁止在Controller开启事务。
- `Optional`主要用于返回值，不用于实体字段和方法参数。
- 时间统一使用UTC存储，API使用ISO-8601。
- 捕获异常时补充上下文并保留cause；禁止空catch。
- 数据库实体不直接作为API响应。

## Go

- 遵循 `gofmt`、`go vet`，CI执行race test（适用时）。
- 接口由消费者定义，保持小而专一。
- 外部I/O必须支持Context超时和取消。
- 错误包装使用 `%w`，不得只记录后吞掉错误。
- 启动的Goroutine必须有所有权、停止条件和回收方式。
- Channel由发送方关闭；禁止通过无缓冲Channel制造隐式死锁。
- 服务实现优雅关闭和就绪/存活检查。

## API

- 路径使用复数名词；状态码语义正确。
- 统一错误：`code/message/traceId/details`。
- 创建类请求支持幂等键；列表接口必须分页并限制最大页大小。
- OpenAPI是外部REST契约；跨仓库事件和Scanner结果使用版本化Schema。
- 删除默认软删除或明确生命周期；危险动作要求二次确认。

## 数据

- PostgreSQL为事实来源；Redis只做可重建数据。
- 所有Schema变更通过Flyway；迁移向前兼容并可在滚动部署期间共存。
- 禁止跨模块直接写表；跨模块通过公开应用接口或事件交互。
- 个人信息、凭据、源码和模型输入分别分类并规定保留期。

## 依赖

新增依赖必须回答：解决什么问题、标准库/现有依赖为何不足、许可证是否允许、维护状态、升级与替换成本。

## AI与MCP

- Prompt和评估集均版本化。
- 不记录隐藏推理；记录输入摘要、工具调用、结果、Token、延迟和错误。
- 工具Schema保持窄且明确；参数做白名单校验。
- 读写工具分离；默认拒绝；每次调用绑定用户、租户、项目和Trace。
- 为循环次数、总时长、Token、并发和费用设置硬上限。
- 来自仓库、ADR和工具的内容均视为不可信，防范间接提示注入。
