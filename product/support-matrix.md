# ArchGuard 支持矩阵

- 状态：Draft
- 适用范围：ArchGuard 当前能力、V1 目标与后续候选
- 所有者：ArchGuard 项目所有者
- 依赖决策：产品定位、公共术语与能力分类草案
- 最后评审：2026-09-08（D01–D04 范围评审；G1 尚未完成）
- 取代/被取代：无

## 本文解决的问题

本文只回答哪些能力当前已经支持、哪些是 V1 目标、哪些只是后续候选。V1 的详细验收标准由 Java/Spring Feature Spec 定义；V1–V5 的优先级与 M0–M13 交付里程碑映射由产品路线图定义。

## 状态口径

| 状态 | 含义 | 可以对外使用“已支持”吗？ |
|---|---|---|
| 已支持 | 实现、自动化验收、使用说明和边界说明均已有可定位证据。 | 可以，但必须同时说明版本和限制。 |
| 未支持 | 当前没有满足“已支持”证据要求的实现。 | 不可以。 |
| V1 目标 | V1 发布必选能力，尚未满足“已支持”的证据要求。 | 不可以。 |
| V1 增强项 | 希望在 V1 周期内交付，但不构成 V1 发布门槛。 | 不可以。 |
| 后续候选 | 有长期价值，版本与优先级尚待路线图决定。 | 不可以。 |
| 非目标 | 当前产品方向明确不承诺。 | 不可以。 |

从“V1 目标”“V1 增强项”或“后续候选”改为“已支持”必须更新证据列；仅有设计、Issue、代码骨架或手工演示均不足以升级状态。

## 当前事实

- 快照日期：2026-09-08。
- 当前交付只有七仓库治理、模板、最小 CI 和 M0 验收报告。
- Platform、Scanner、Analyzer、公共扫描契约、规则实现和端到端用户流程均尚未交付。
- 所以本矩阵中没有任何产品或分析能力处于“已支持”；Java/Spring 也是 V1 目标，不是当前能力。

## 技术栈与分析支持

| 技术栈或输入 | 当前状态 | 目标状态 | V1 边界或已知限制 | 升级为已支持所需证据 |
|---|---|---|---|---|
| Java 源码 | 未支持 | V1 目标 | 深度支持方向；语法版本、依赖抽取和规则清单待 V1 Feature Spec。 | 固定版本矩阵、正常/违规/失败样例、确定性黄金测试和限制说明。 |
| JVM 字节码 | 未支持 | V1 增强项 | 不作为 V1 发布门槛；与源码结果的优先级仍待确认。 | 固定 classfile/JDK 范围、兼容测试、冲突处理和可复现结果。 |
| Spring / Spring Boot | 未支持 | V1 目标 | 深度支持方向；框架版本、Bean、注入、分层与模块语义待确认。 | 框架版本矩阵、最小样例、规则验收、Evidence 与不支持项。 |
| Maven 工程描述 | 未支持 | V1 目标 | 只读取 POM 等静态元数据，不执行构建、插件或目标仓库代码。 | 支持元素、解析边界、无构建执行验证及失败诊断。 |
| Gradle 工程描述 | 未支持 | V1 增强项 | 只读取可安全识别的静态元数据，不执行插件、任务或目标仓库代码。 | 支持语法、动态配置降级行为、无执行验证及失败诊断。 |
| Kotlin / Scala | 未支持 | 后续候选 | 运行于 JVM 不等于已被 Java Analyzer 支持。 | 独立能力声明、语法/字节码边界、样例和验收证据。 |
| Go 源码 | 未支持 | 后续候选 | Gateway 使用 Go、Samples 计划包含 Go，均不代表 Go 分析支持。 | 独立 Analyzer、规则范围、样例和验收证据。 |
| TypeScript / JavaScript | 未支持 | 后续候选 | V1 不实现 TypeScript Analyzer。 | 独立 Analyzer、生态版本范围、样例和验收证据。 |
| 容器与部署配置 | 未支持 | 后续候选 | Deploy 仓库负责部署 ArchGuard，不是 Deployment Analyzer。 | 明确输入格式、规则、隔离边界、样例和验收证据。 |
| 跨技术栈关联分析 | 未支持 | 后续候选 | 至少依赖两个已支持 Analyzer 和稳定的公共事实模型。 | 跨 Analyzer 契约、冲突语义、端到端样例和回归测试。 |

## 产品工作流支持

| 产品能力 | 当前状态 | 目标状态 | 边界 | 升级为已支持所需证据 |
|---|---|---|---|---|
| Project 与 Repository 治理 | 未支持 | V1 目标 | 先形成最小登记、归属与查询闭环。 | Feature Spec、API/权限测试、迁移和使用说明。 |
| 手动创建 Scan 与查询状态 | 未支持 | V1 目标 | 状态、幂等、失败和取消语义待规格化。 | 状态机测试、API 契约、审计和端到端验收。 |
| Java/Spring 扫描结果 | 未支持 | V1 目标 | 结果须区分 Fact、Finding、Evidence 和 Diagnostic。 | 版本化契约、Schema 验证、黄金样例和部分失败测试。 |
| Policy 与确定性 Rule | 未支持 | V1 目标 | LLM 不负责确定性违规判断。 | 规则规格、配置校验、正反例、稳定排序和回归测试。 |
| PR 反馈 | 未支持 | 后续候选 | 明确不属于 V1；默认只读与最小权限。 | GitHub 权限、Webhook、安全、幂等和端到端证据。 |
| MCP 只读查询 | 未支持 | 后续候选 | 明确不属于 V1；Gateway 仓库存在不代表工具已交付。 | Tool Schema、授权、审计、限流与安全评估。 |
| AI 解释与建议 | 未支持 | 后续候选 | 明确不属于 V1；只能基于可验证事实并经过 Schema、权限和业务校验。 | 版本化评估集、安全门禁、成本与延迟报告。 |
| 商业化多租户 SaaS | 未支持 | 非目标 | 当前项目不承诺商业化、公开托管或生产级租户规模。 | 需要新的产品决策，不由当前路线图默认继承。 |

## 版本与里程碑口径

- V1、V2 等表示用户可感知的产品能力版本。
- M0–M13 表示工程交付顺序和关卡，不等同于产品版本。
- V1 发布门槛只计算“V1 目标”；未交付“V1 增强项”不阻塞 V1，但不得声称该增强项已支持。
- 本文确定 Java 源码、Spring 语义和 Maven 静态元数据为 V1 必选范围；JVM 字节码与 Gradle 静态元数据为 V1 增强项。
- PR、MCP 和 AI 能力明确不属于 V1；它们的后续版本与 M0–M13 映射尚待产品路线图确认。
- 后续候选不得在路线图确认前自行标注 V2、V3 等版本。

## 目标状态

- 所有 README、Feature Spec、架构文档和对外说明引用同一状态口径。
- 每项“已支持”声明都能定位到实现版本、自动化测试、样例和限制说明。
- 每次发布更新快照日期，只修改有证据变化的行。

## 非目标

- 不在本文定义 Scanner、Analyzer Registry、进程协议或动态插件机制。
- 不冻结 ScanRequest、ScanResult 或 Rule Schema。
- 不给后续候选安排产品版本或承诺日期。
- 不用计划中的 Samples、Gateway 或 Deploy 能力推导分析支持。

## 已接受决策

- 当前建设不以多语言全覆盖为目标。
- 未实现或未验证的能力不得描述为已完成。
- Scanner 契约须版本化且独立于 Platform 内部类。
- V1 只读 Maven 静态元数据，JVM 字节码与只读 Gradle 静态元数据为增强项；任何目标仓库构建、插件或任务执行均不进入 V1。
- PR 反馈、MCP 查询和 AI 解释明确排除在 V1 之外。

Java/Spring 的 V1 产品边界仍为 Draft，须经 G1 评审确认。
