# ArchGuard 产品定位

- 状态：Accepted
- 适用范围：ArchGuard 长期产品定位与 V1 技术栈边界
- 所有者：ArchGuard 项目所有者
- 依赖决策：M0 仓库与治理基线
- 最后评审：2026-09-09（同步 G4 V1 详细范围；G1 产品结论不变）
- 取代/被取代：无

## 本文解决的问题

本文只回答 ArchGuard 是什么、当前已经是什么，以及 V1 选择在哪个技术栈形成深度能力。目标用户、指标和完整非目标由后续产品章程定义；实现边界、执行模型和扫描契约不在本文决定。

## 一句话定位

ArchGuard 的长期定位是面向多技术栈的软件架构治理平台：把代码与工程配置中的可验证事实、架构规则和决策记录连接起来，为团队提供可追踪、可解释的架构反馈。

V1 不追求多语言广度，优先深度支持 Java/Spring；“多技术栈”描述长期产品方向，不表示当前或 V1 已支持所有语言和框架。

## 当前事实

- 截至 G4，七个仓库已完成 M0 治理基线和 M1 文档关卡，业务工程骨架、Analyzer、机器扫描 Schema 和端到端流程均未交付。
- 当前可以评审的是产品与工程边界，不能声称已具备 Java、Spring、Go、TypeScript 或部署配置分析能力。
- `archguard-docs` 是产品、需求、总体架构、ADR 和跨仓库规范的事实来源。
- Platform、Scanner、Registry、Analyzer 和七仓库关系已通过 G2 架构边界评审；字段级契约、Rule 职责和安全默认值已通过 G3 契约与安全评审。

## 目标状态

### 长期定位

- 用语言无关的治理工作流承载项目、仓库、策略、扫描、证据、审计和集成。
- 通过可演进的分析能力覆盖不同语言、框架和工程制品，而不是把平台绑定到单一解析器。
- 以确定性事实和规则作为可验证基础，允许 AI 做解释、归纳和低风险建议。
- 让同一条需求能够追踪到架构边界、决策记录、交付里程碑和验收证据。

### V1 聚焦

- 平台能力围绕 Java/Spring 仓库的登记、扫描触发、结果查询、证据展示和审计形成最小闭环。
- 分析能力以 Java 源码和 Spring 语义为必选核心，并只读取 Maven 静态元数据；精确版本、规则和不支持项已由 [D14 V1 Feature Spec](../requirements/v1-java-spring-feature-spec.md)冻结。
- JVM 字节码与 Gradle 静态元数据是 V1 增强项，不作为 V1 发布门槛；V1 不执行目标仓库的构建、插件或任务。
- PR 反馈、MCP 查询和 AI 解释不属于 V1，具体版本由产品路线图安排。
- V1 的深度优先于同时支持 Go、TypeScript 等更多语言。
- V1 能力只有在实现与验收证据齐备后才可从“目标”改为“已支持”。

## 非目标

- 本文不选择 Scanner 内部结构、Analyzer Registry 归属或进程模型。
- 本文不冻结 ScanRequest、ScanResult、Fact、Finding 或 Diagnostic Schema。
- 本文不承诺商业化、多租户规模、公开 SaaS 或任意仓库即插即用。
- 本文不把 Platform 或 Gateway 的实现语言等同于被分析语言支持。
- 本文不为 Go、TypeScript、Kotlin、Scala 或部署配置声明交付版本。
- 本文不把 JVM 字节码、Gradle、PR、MCP 或 AI 能力作为 V1 发布前提。

## 已接受决策

- 初期产品建设以可运行、可测试、可部署、可解释的架构治理能力和演进证据为目标，不以商业化或多语言全覆盖为目标。
- 确定性规则是事实基础；LLM 输出是不可信输入，只承担解释、归纳与低风险建议。
- 规范性文档必须区分当前事实、目标状态和待决策项。
- D01–D04 范围评审已确认：Java 源码、Spring 语义与只读 Maven 元数据是 V1 必选范围；JVM 字节码与只读 Gradle 元数据是 V1 增强项；V1 不执行目标构建；PR、MCP 和 AI 能力不进入 V1。

“长期面向多技术栈、V1 深度支持 Java/Spring”已在 G1 评审中成为已接受产品边界。

## 开放问题

- D14 已确定 V1 的 Java/Spring/Maven 版本、能力、规则和证据边界；何时有足够实现与验收证据升级为“已支持”？
- V2–V5 何时具备足够证据进入日期承诺和 Feature Spec？
- JVM 字节码与 Gradle 增强项在什么条件下升级为后续版本的必选能力？
- V1 的成功指标、防护指标和明确用户画像是什么？

这些问题分别由 D15 发布证据、产品章程和产品路线图处理，不在本切片提前回答。
